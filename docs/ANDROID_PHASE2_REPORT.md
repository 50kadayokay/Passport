## 1. Android environment installed/configured

Installed via Homebrew, no `sudo` and no password required (the `openjdk` formula was used instead of the `temurin` cask precisely to avoid a privileged install into `/Library/Java`).

| Component | How |
|---|---|
| JDK 21 | `brew install openjdk@21` (keg-only; `JAVA_HOME` set per-command, **not** written to your shell profile) |
| Android cmdline-tools | `brew install --cask android-commandlinetools` |
| SDK packages | `sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.1.0" "emulator" "system-images;android-36;google_apis_playstore;arm64-v8a"` |

## 10. Android-specific issues discovered

Recorded, **not fixed** in Phase 2.

### A. `Error injecting safe area CSS: TypeError: Cannot read properties of null (reading 'style')` — 3× at startup
Capacitor 8's built-in `SystemBars` plugin injects `--safe-area-inset-*` CSS custom properties, and fires before `document.documentElement` exists. Harmless here: the app reads `env(safe-area-inset-*)`, not those custom properties, and on WebView ≥140 (this emulator) Capacitor passes real insets through natively — which is why the layout is correct in every screenshot. Needs revisiting for older WebViews (<140), where Capacitor pads the decor view instead. → **inset/layout phase**

### B. Hardware back button — unhandled (expected)
Not tested per your instruction; no `@capacitor/app` listener exists. Back will exit the app from sub-screens. → **Phase 3**

### C. Google authentication — not configured (expected)
`SocialLogin` plugin registered, but `socialInit()` passes only `iOSClientId`. Android needs `webClientId` plus Android OAuth clients per signing cert. → **Phase 4**

### D. Push — not configured (expected)
`PushNotifications` plugin registered; no `google-services.json`, no FCM. → **Phase 5**

### E. `navigator.share` — not tested (expected)
→ **Phase 6**

### F. External news thumbnails fail to load
13 of 21 `<img>` on the guest profile did not load, all `https://www.juniorminingnetwork.com/images/jmn_feeder/...`. Company-owned imagery (logo, hero, icons) loaded fine. Cause not yet established — could be emulator egress, hotlink protection, or source-side 403. Worth checking whether iOS shows the same. → **Phase 7**

### G. Emulator `devices.xml` warning on AVD creation
`avdmanager` could not read the device catalogue from the cmdline-tools install and fell back to a default profile. Cosmetic; the AVD works. Installing Android Studio would supply the catalogue.

### H. Template test boilerplate has the wrong package
`android/app/src/{test,androidTest}/java/com/getcapacitor/myapp/` — stock Capacitor template leftovers. Left untouched deliberately (no unrelated refactoring).

## 11. Anything that could affect iOS / web

**One item, and it is not Android-specific.**

The guest "smart-banner" (`PassportProto.jsx` ~line 10720) is gated on `guest && !bannerOff` — **not** on platform. So when a signed-out user views a shared/QR profile it renders inside the *native* app too, showing a "Get the app" button and the stale pre-rebrand wordmark **"Passport"** with a "P" avatar. This affects the **iOS QR-scan / shared-link guest flow identically**; it is a pre-existing cross-platform content bug that Android testing surfaced, not a regression introduced here. Not fixed, since it touches shared shipping code and is outside Phase 2.

Otherwise: no shared code changed, no API route changed, no migration added, no iOS file touched, and no dependency version moved. The `@capacitor/android` addition cannot affect the iOS or web runtime.
